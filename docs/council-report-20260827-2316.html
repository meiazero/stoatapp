LLM Council · Architecture Decision

Stoat Complete Refactor

Five independent advisors, five anonymous peer reviews, primary-source verification, and chairman synthesis.

Decision: preserve the working Solid/Electron/LiveKit product while moving canonical domain and sync invariants into deep Rust modules. Intend a simple single-node deployment, but require proof before replacing persistence or clients. Choose the native toolkit by one fixed accessibility/media/platform probe. Make capability-based WASM extensions the strategic expansion direction.

Chairman verdict

Product boundary

User-controlled, extensible communication—not a simultaneous Discord, Matrix, Slack, Twitch, and Notion replacement.

Permanent seam

A canonical domain model and versioned event/sync envelope. It owns ordering, replay, idempotency, gaps, tombstones, revocation, compatibility, and migration.

Deployment

Rust modular monolith for API/event plane; isolated media and hazardous workers. Intended single-node SQLite/filesystem profile plus proven scale adapters.

Security

Per-device identity, recovery, revocation, retention, deletion, plugin capabilities, and explicit server-readable/trusted-agent/zero-knowledge modes.

The first runnable gate

Write the canonical domain model and versioned event envelope, then run a deterministic offline/reconnect simulation against the existing product.

  1. Duplicate, reordered, and missing delivery.
  2. Tombstones, long-offline clients, and stale writes.
  3. Permission revocation and device loss.
  4. Snapshot recovery and eventual convergence.

If this contract is not deterministic, no database, native toolkit, plugin system, E2EE design, or frontier protocol is ready to anchor the refactor.

Advisor briefs

The Contrarian
Preserve the working stack and reject unsupported certainty. Database interfaces do not prove migration semantics. Keep MongoDB and S3-compatible storage until reversible load, recovery, RPO, and RTO gates pass. Treat frontier technologies as product programs.
The First Principles Thinker
Reframe Stoat as local-first, self-hostable communication. Build deep Rust modules for rules and sync, retain platform-specific UI state, use a modular monolith, and make accessibility a toolkit-selection constraint.
The Expansionist
Pursue a Rust-core architecture, specialized clients, GStreamer media workflows, and a capability-based WASM ecosystem. Use collaborative documents and selective E2EE to expand beyond Discord.
The Outsider
Narrow the product boundary. Validate real low-bandwidth, constrained-device, and screen-reader workflows before architecture choices. Sequence reliability and offline behavior before frontier capabilities.
The Executor
Migrate by preserved contracts and objective gates. Fix measured defects first, introduce pure invariants, prove data replacements, select the native toolkit through one artifact, and delete legacy paths only after two stable releases and rehearsed rollback.

Peer review highlights

Why the Executor won 4 of 5 reviews
It supplied the strongest reversible sequence, explicit sync semantics, recovery/load gates, and rollback discipline. Its weakness was leaving too many end-state decisions open.
Why First Principles won 1 review
It connected a coherent product identity to deep seams and adapter-based architecture without forcing a premature rewrite.
Blind spots found by reviewers
Canonical domain ownership, quantitative convergence criteria, identity recovery, threat models, abuse/moderation, privacy/retention, SLOs, observability, incident response, support budgets, upgrade compatibility, and deletion ownership.
